Problem statement

Neural Kinematics and Reinforcement Learning for Collision-Free Space Manipulator Path Planning

Level 1 (this Studio)

Use simulated multi-axis space manipulator joint data to develop a kinematics-aware AI/ML model that predicts collision-free trajectories and computes joint angles to prevent self-collision with the satellite body.

Level 2 (next stage)

Implement a lightweight Deep Reinforcement Learning (DRL) policy agent, optimised for low compute, that re-routes the manipulator path in real time when unexpected obstacles or hardware position errors occur.

Dataset (from the brief): OpenRAVE / PyBullet manipulator kinematics and space-robot simulation. We use PyBullet and generate the data ourselves by simulation, so no download is needed.

In simple words

A robot arm is a chain of rotating joints. To grab something, the controller must answer: “which angle should every joint have so the gripper ends up exactly here, pointing this way?” This is called inverse kinematics (IK). The answer must also be safe: the arm must never hit itself (or, on a satellite, the satellite body).

Classical solvers find the angles by trial-and-improve steps. They are accurate but slow-ish, need a good starting guess, and know nothing about collisions. Level 1 trains a neural network to give a fast, collision-aware first answer, then finishes it with a small numerical solver to reach < 1 mm and < 1°.

Scope agreed for Level 1

  • The final space manipulator's kinematic model is not available yet, so mentors approved validating the method on standard, well-documented arms: xArm6 (6-DOF), KUKA LBR iiwa (7-DOF) and Franka Panda (7-DOF).
  • A robot is just one entry in robot_config.py (URDF file + joint names). When the space manipulator's URDF exists, adding it is one entry; data generation, training and evaluation stay the same.

Key ideas & maths

Only the notation you need, with simple symbols.

Symbols

Forward kinematics (FK) – the easy direction

Given the joint angles, multiply the transforms of all links one after the other to get the gripper pose:

(p, q) = FK(θ) = T1(θ1) · T2(θ2) · … · Tn(θn) Each Ti is a 4×4 matrix (rotation + translation) for link i. PyBullet computes this for us. FK always has exactly one answer.

Inverse kinematics (IK) – the hard direction

find θ such that FK(θ) = (ptarget, qtarget) There may be 0, several (6-DOF) or infinitely many (7-DOF) answers. There is no simple formula for a general arm.

Why 7-DOF is harder: a pose has 6 numbers (3 for position, 3 for rotation). A 6-DOF arm has exactly 6 unknowns, so it has a finite set of solutions (e.g. elbow up / elbow down). A 7-DOF arm has one extra joint, so a whole family of solutions reaches the same pose – the elbow can swing while the hand stays still (the “null space”).

Errors we report

position error ep = ‖ p(θ̂) − ptarget ‖ (in mm)
orientation error eR = 2 · arccos( |⟨q(θ̂), qtarget⟩| ) (in degrees) ‖·‖ is the straight-line distance; ⟨·,·⟩ is the dot product of the two quaternions. “Accuracy within 30 mm” = % of targets with ep ≤ 30 mm.

Angle encoding with sin / cos

−180° and +180° are the same direction but numerically far apart, which confuses a regression loss. So the network outputs two numbers per joint and we decode them with atan2:

network output per joint: ( sin θi, cos θi ) → θi = atan2( sin θi, cos θi )

The seed

If two different joint answers reach the same pose, a network trained without extra information learns their average, which reaches neither. Giving it a seed s (in real use: the arm's current angles) turns the question into “the solution near this seed”, which is well defined.

network: θ̂ = fw( p, q, s ) with s = θtrue + noise, noise ~ N(0, 0.3²) per joint during training fw is the neural network with weights w. N(0, 0.3²) is random noise with standard deviation 0.3 rad ≈ 17°.

Collision-aware training loss

A small second network C(θ) learns the probability that a configuration self-collides. While the IK network trains, its prediction is passed through the (frozen) collision network and colliding answers are penalised:

Loss = mean( ‖ [sin θ̂, cos θ̂] − [sin θ, cos θ] ‖² ) + λ · mean( σ( C(θ̂) ) ), λ = 0.05 σ is the sigmoid (turns a score into a probability 0…1). Larger λ = safer answers but slightly less accurate poses.

6-DOF (xArm6)

  • Unknowns = 6 = pose numbers → a few discrete solutions.
  • Joint 3 range is −225° … +11°, wider than atan2's −180…180°. We shift each angle by ±360° into the limits (“wrap to limits”); this alone raised success from 77% to 99.8%.

7-DOF (KUKA, Panda)

  • Unknowns = 7 > 6 → infinitely many solutions per pose (elbow swing).
  • The seed input picks one consistent solution branch.
  • Panda's hand touches its own links by construction; the clean/precision generators ignore such always-touching pairs (otherwise 100% of poses look “colliding”).

A real bug we caught

The xArm6 URDF has a fixed world_joint at index 0, which silently shifts every joint index by one if you assume indices 0…5. robot_config.py resolves joints by name to prevent this. Self-collision checks also only work when the URDF is loaded with URDF_USE_SELF_COLLISION (and …_EXCLUDE_PARENT so touching parent/child links are not false alarms).

Dataset generation

We create labelled examples by simulation: pick angles → compute pose → check collision.

random θ within joint limits→FK(θ) = (p, q)→self-collision? (0 / 1)→save (θ, p, q, label)

Sampling

  • Uniform (70%): each joint θi ~ Uniform(loweri, upperi).
  • Near the limits (30%): joints pushed towards their extremes, where self-collisions concentrate.
  • Each sample is labelled colliding if any two non-parent/child links touch (PyBullet contact check).
  • Only collision-free samples train the IK network; all samples train the collision classifier.

Train / validation / test split

For every training run the Studio first removes a held-out test split (15%) that the network never sees. The rest is split 85 / 15 into train / validation. All “test” numbers in this guide are on that unseen split.

Training & models

Two networks: a collision classifier, then the IK network that uses it.

1 · Collision classifier C(θ)

  • Small MLP 64 → 64 → 1, input = joint angles, output = collision score (sigmoid → probability).
  • Trained first (15 epochs), then frozen. Fast enough to call thousands of times per second – reusable in Level 2.
  • Measured (xArm6, run 20261005-155310, 3,000 unseen poses): 97.2% accuracy, 90.8% precision, 87.1% recall.

2 · IK network fw(p, q, s)

input [ x, y, z, qx, qy, qz, qw, s1 … sn ] (7 + n numbers) → output [ sin θ̂1 … sin θ̂n, cos θ̂1 … cos θ̂n ] (2n numbers)
  • Base model (train_ik.py): MLP 256 → 256 → 128 → 2n, ReLU, ≈104k parameters.
  • Optimiser Adam, learning rate 0.001, batch 256, loss as in “Key ideas” (MSE + 0.05 · collision penalty).
  • Automatic stop: training ends early when e.g. ≥ 90% of samples land within the tolerance for 2 epochs in a row.
  • Trains on the GPU (RTX 3060) when available; every run is saved under ui/workspace/library/runs/<run>/.

Refinement: network + LM solver

The network gives a fast first guess; a few solver steps make it exact.

No published pure neural IK reaches sub-millimetre accuracy. Systems that do (e.g. IKFlow; Lu, Zou & Jiang 2022 on the xArm6) use the network as a starting point and finish with a numerical solver. We use Levenberg–Marquardt (LM), implemented batched in PyTorch (refine/lm_solver.py).

One LM step

Δθ = ( Jᵀ J + λ I )−1 Jᵀ e , θ ← clamp( θ + Δθ , limits ) , λ = ‖e‖² + 10−6 e = [position error; rotation error] (6 numbers). J is the 6 × n Jacobian: how much the gripper moves when each joint moves a little. I is the identity matrix. λ (“damping”) keeps steps small when far from the target.

The full pipeline (Run Inference → Refinement = LM)

  1. Network predicts θ̂ from (p, q, s).
  2. Wrap to limits: shift each angle by ±360° to the copy inside the joint limits closest to the seed.
  3. LM, 30 iterations from the network answer and from the seed; keep the better one.
  4. Random restarts (16) only for targets still outside 1 mm / 1°.
  5. PyBullet check: FK error, joint limits and self-collision verified independently.
  6. Collision-free retry: if the answer collides, search another arm posture and keep the first one PyBullet confirms.

Speed

  • IK network on the RTX 3060: 0.38 ms for one target, 0.16 µs per target in a batch.
  • LM solver: about 0.03 ms per target on the GPU when 2,000 targets are solved together (10 iterations, warm start).
  • One interactive “Run inference” in the Studio takes ~15–95 ms because it also runs the PyBullet checks and drawing.

Honest limits

  • The pure network is not accurate enough on its own (best 23 mm); the < 1 mm result comes from network + LM.
  • Most trained runs are for the xArm6. The 7-DOF arms are supported end to end (data, training, LM solver – FK matches PyBullet to ~1e-4 mm on KUKA and Panda), but have fewer benchmarked runs so far (KUKA network alone: 134.8 mm on 5,000 targets).

Level 2 – problem & approach

Real-time re-routing with a lightweight Deep Reinforcement Learning agent.

Problem statement (Level 2)

Implement a lightweight Deep Reinforcement Learning (DRL) policy agent optimised for low compute overhead that dynamically re-routes the manipulator path in real time when unexpected geometric obstacles or hardware position errors occur.

In simple words

Level 1 tells us where the joints must end up (the goal configuration from neural IK + LM). Level 2 decides how to get there, one small step at a time, while things go wrong: an obstacle suddenly blocks the way, obstacles drift, a joint slips, or the motors do not move exactly as commanded. The agent looks at the situation every step (a few microseconds of computing) and bends the path around the problem.

target pose→Level 1: neural IK + LM → goal joints θgoal→Level 2: DRL agent, step by step→arm reaches the goal without collisions

Approach

  • Simulation: PyBullet (as in Level 1), xArm6 (6-DOF) and KUKA iiwa (7-DOF), with obstacles and injected hardware errors.
  • Algorithm: PPO (proximal policy optimisation), written in plain PyTorch – no extra RL library.
  • Residual policy: the agent outputs a correction on top of the straight path to the goal. With a zero correction it behaves like the simple controller, so it only has to learn when and how to deviate.
  • Kinematics-aware input: for every nearby obstacle the agent receives the joint-space “escape direction” computed from the robot Jacobian, so it does not have to rediscover the arm's kinematics.
  • Lightweight: a 2 × 64 network (≈ 9–10 k weights) that runs as plain NumPy on one CPU core.
  • Fair comparison: two classical baselines on identical scenarios – the straight path and an artificial potential field.

Level 2 – environment & maths

A Markov decision process: state → action → next state + reward.

One step

θt+1 = clip( θt + Δmax · ( (1 + g) ⊙ ut ) + b , joint limits ) Δmax = 0.03 rad ut ∈ [−1, 1]n is the command, g a per-joint actuator gain error (±20%), b a small bias, ⊙ element-wise product.

Residual action

ut = clip( ustraight + 2 · at , −1, 1 ), ustraight = clip( (θgoal − θt) / Δmax , −1, 1 ) at ∈ [−1, 1]n is the agent's correction. at = 0 gives the straight-path baseline.

Unexpected events (randomised every episode)

EventWhat happens
Obstacles on the path1–2 spheres (3.5–7.5 cm) placed on the straight path, ≥ 10 cm from the arm at the start.
Sudden obstacleA sphere appears mid-motion on the path ahead (≥ 12 cm from the arm when it appears).
Drifting obstaclesObstacles move with a small random velocity.
Joint slip (hardware)One joint suddenly jumps by N(0, 0.25 rad) ≈ ±14°.
Actuator error (hardware)Gain error ±20% per joint and a small bias for the whole episode.

The goal pose always keeps ≥ 12 cm clearance (Level 1 would choose a collision-free goal).

What the agent sees (observation)

  • joint angles (normalised), joint error to the goal θgoal − θ, gripper position and gripper-to-goal vector,
  • positions of all links relative to the gripper, the previous action,
  • for each of 3 obstacle slots: position, closest-point vector robot → obstacle, clearance d, radius, active flag, and the escape direction (below). 87 numbers in total for the xArm6.

Kinematics-aware escape direction

g = Jc(θ)ᵀ · n̂ , ĝ = g / ‖g‖ , w = max(0, 1 − d / 0.25 m) Jc is the 3 × n position Jacobian of the robot point closest to the obstacle (from PyBullet); n̂ is the unit normal from the obstacle to that point. Moving the joints along ĝ pushes the robot away fastest. The agent receives w · ĝ.

Reward

rt = 3 · (Dt−1 − Dt) − 0.01 − 0.02‖at‖² − 0.02‖ut − ut−1‖² − 1 · max(0, (0.08 − dmin)/0.08) − 0.3 · σ(C(θt))
       + 15 if reached − 25 if collision − 10 if timeout D = ‖θgoal − θ‖ + 2‖pgoal − p‖ (progress), dmin = smallest clearance to any obstacle, C = the Level 1 collision classifier (self-collision risk), σ = sigmoid. Reached = every joint within 0.06 rad and gripper within 2 cm.

Baselines

  • Straight path: u = ustraight – Level 1 IK + interpolation, no obstacle awareness.
  • Artificial potential field (APF): u = clip(ustraight + 2 Σk wk² ĝk) – the classical reactive method (Khatib 1986, here in joint space). Avoids obstacles but can get stuck in local minima.

Level 2 – agent, training & compute

PPO with a tiny network; GPU where it helps, CPU where it must.

Network

π(a | s) = N( tanh(MLP64,64(ŝ)) , diag σ² ) V(s) = MLP64,64(ŝ) ŝ = running-normalised observation. The actor (the only part that is deployed) has ≈ 9–10 k weights.

PPO objective

L = −E[ min( ρ A , clip(ρ, 1 − 0.2, 1 + 0.2) A ) ] + 0.5 (V − R)², ρ = πnew(a|s) / πold(a|s) A = generalised advantage estimate (γ = 0.995, λ = 0.95). Adam, learning rate 3·10⁻⁴ decaying to 0, 6 epochs per update, mini-batch 2048.

Training throughput on the laptop: about 5,000–6,000 simulated steps per second; 5 M steps take about 15–20 minutes.

Reading the numbers

  • Collisions: the straight path (Level 1 goal + interpolation) collides in 20–50 % of episodes with obstacles; the DRL agent in 1.5–2 %.

  • Hardware errors: joint slips and actuator errors are recovered by all controllers in ~98.5 % (closed-loop control); the rest are slips that cause a self-collision.

How Level 1 and Level 2 connect

Two different kinds of learning that share the robot, the kinematics and the collision knowledge.

target pose (where the gripper must go)→Level 1: neural IK + LM → goal joints θgoal→Level 2: DRL agent drives θ → θgoal, re-routing around problems

Learning point of view

Level 1 – neural IKLevel 2 – DRL re-routing
Type of learningSupervised: learn a function from labelled examplesReinforcement: learn a behaviour from rewards
Question it answers“Which joint angles put the gripper at this pose?” (one answer)“Which small move should I make now?” (every step, ~50–300 per motion)
DataPrepared dataset (FK of random joint configurations)Generated while training by acting in the simulator
Loss / objectiveMSE on (sin θ, cos θ) + collision penaltyPPO: maximise expected reward
NetworkMLP, ~0.1–2 M weights, runs once per targetMLP 2 × 64, ~10 k weights, runs every control step
OutputGoal joint configurationJoint motion command (correction)

The two are trained separately: training Level 2 never changes Level 1's weights, and Level 1 does not need Level 2.

What Level 2 takes from Level 1 today

  • The robot set-up: the same robot_config.py registry, URDFs and PyBullet loading with self-collision checks.
  • The collision classifier C(θ) from models/<robot>_collision_net.pt (trained by Level 1's train_ik.py): Level 2's reward subtracts 0.3 · σ(C(θ)) every step, so the agent learns to stay away from self-collision-prone postures. If you retrain that file, retrain the Level 2 agent too (its reward changed).
  • Kinematics: Jacobian-based geometry – Level 1's LM solver uses the Jacobian to refine IK answers, Level 2 uses it for the escape direction.
  • The goal: Level 2 is trained on random self-collision-free goal configurations – exactly the kind of answer Level 1 produces.

Training vs. use

Level 2 is trained on randomly sampled goal configurations (stand-ins for IK answers), with the collision classifier from models/. In use, the two levels are connected on the Mission · L1 + L2 page: a target pose is solved by a chosen Level 1 run (network + LM) and the Level 2 agent drives the arm to that IK goal – see the Mission section of this guide.

Mission – the complete system (Level 1 + Level 2)

Solve IK, estimate the trajectory, then move while avoiding dynamic obstacles and self-collision.

Project goal in one run

Given a target pose for the gripper, compute collision-free joint angles (Level 1), estimate the path and check it, then move the arm in real time, re-routing around moving and suddenly appearing obstacles and recovering from hardware position errors (Level 2) – without ever colliding with obstacles or with itself.

① target pose (p, q)→② IK: Level 1 network + LM → θgoal→③ trajectory estimate & check→④ DRL movement (Level 2)→⑤ final pose check

① Target pose

Either a random reachable pose (the gripper pose of a random self-collision-free configuration) or your own position (x, y, z) and orientation (roll, pitch, yaw). The arm starts from its current joints θstart.

② Solve IK (Level 1)

θ̂ = fw(p, q, s = θstart) → θgoal = LM-refine(θ̂) → shift each joint by k·360° to the copy closest to θstart The network is seeded with the arm's current joints, so it picks the solution branch nearest to where the arm is. Accepted only if ‖p(θgoal) − p‖ ≤ 1 mm, orientation ≤ 1°, inside joint limits and self-collision free (PyBullet check). The ±360° shift keeps the same pose but avoids a needless full turn of the wrist joints.

③ Trajectory estimate

θ(s) = θstart + s · (θgoal − θstart), s = 0 … 1 (40 waypoints) For every waypoint the gripper position is computed (FK), plus the clearance to the obstacles known at the start and a self-collision check. Waypoints are coloured: ok / near (< 5 cm) / predicted collision. This is the path a planner without re-routing would follow – if it is blocked, re-routing is needed.

④ Move & re-route (Level 2)

The DRL agent drives θstart → θgoal step by step (Δθ ≤ 0.03 rad per step). While it moves, obstacles drift, a new obstacle can appear on the path, a joint can slip and the motors have gain/bias errors. Every step it decides from the measured state; an episode fails on contact with an obstacle or self-collision. When it arrives (2 cm / 0.06 rad) a short final approach servos exactly onto θgoal in 0.01 rad steps, each one collision-checked.

⑤ Final pose check

ep = ‖p(θfinal) − ptarget‖, eR = 2 arccos |⟨q(θfinal), qtarget⟩| Measured against the original target pose, so it includes the IK error and the movement.

How the pieces cooperate

NeedSolved by
Joint angles for a poseLevel 1 IK network (fast first guess) + LM solver (exact)
No self-collision at the goalLevel 1 collision-free check / retry in the LM step
No self-collision on the wayLevel 2 reward uses Level 1's collision classifier; PyBullet checks every step

Hardware position errorsClosed-loop control: every step starts from the measured joints
